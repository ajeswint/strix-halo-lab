THE CRITICAL RULE: hidden tests never steer anything
============================================================
The hidden grading tests (each task's `tests` string in tasks_v10.py, graded at FRESH_SEED 104729 exactly as debate.py report does) must NEVER be shown to the model and NEVER used for selection, retries, stopping, or any decision inside the loop. Only three signals may steer: (1) VISIBLE tests, (2) model-written tests, (3) static checks. Hidden grading happens once per (task, seat, arm), on the final selected code, after the loop is over.

What I found (verify it yourself and state it in the spec): in v10 there is NO separate visible test suite. Every one of the 90 tasks (all four families: formats, number_theory, graphs_geometry, simulation_dp) has a single `tests` string that contains (i) the prompt's "Examples:" asserts verbatim, (ii) extra fixed asserts and rejection cases NOT in the prompt, and (iii) a seeded oracle loop at random.seed(10000+NN). The final grade swaps that seed for 104729, but (i) and (ii) are identical between the "visible seed" and the fresh grade. Therefore:
 - agent.py's existing loop (which feeds back failures from the full `tests` at the visible seed) VIOLATES the rule and must NOT be reused for this experiment. Say so in the spec.
 - Visible split (identical policy for all four families): visible tests = ONLY the examples already written in each task's prompt "Examples:" block, i.e. lines of the form `- f(args) == value` and the `- ValueError: call, call, ...` lists (some prompts may use `->` or other phrasings; handle the forms that actually occur and count the rest). Every visible check must be derivable from the prompt text alone: write a unit test that asserts each extracted call/expected-value literal appears in that task's prompt, and that every task's `ref` passes all its visible asserts in the sandbox. Report per-family counts: tasks with >=1 visible assert, total asserts, tasks where extraction failed (those fall back to static checks + model tests only, flagged `no_visible`, and are listed in the spec). Never read from `tests` to build visible tests.
 - Enforce in code, not just prose: the in-loop code path must receive tasks with only id/prompt/visible (no `tests`, no `ref`).
